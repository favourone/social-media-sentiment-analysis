# 高校校园公共安全与民生服务舆情态势可视化平台·5 分钟现场演示脚本

## 演示前

1. 用 Conda `cv` 启动 `python -m web`，登录并保持在“今日态势”。
2. 点一次“载入离线演示案例”，确认是 54 条、3 个事件、39 条风险词信号。
3. 演示电脑关闭浏览器缩放，使用 1920×1080 或 1440×900；保留一份 JSON/CSV 备用数据。
4. 不依赖现场微博扫码、外部 LLM 或公网 RSS。

## 0:00–0:35：问题与价值

> 高校食品安全、校园反诈和公共服务故障往往散落在不同公开渠道。管理人员真正需要的是：异常在哪里、它如何演化、证据来自哪里、下一步做什么。校园舆情雷达把这个过程组织为“发现、聚合、核验、处置”四步。

指向首屏四步叙事。

## 0:35–1:10：数据边界

点“载入离线演示案例”。

> 为了让评委在无网络环境也能复现，此处使用 54 条固定合成记录。页面显式标注“合成演示数据”，并公开样本量、有效时间和情感方法；我们不把演示数据伪装成真实校园事件。

指向数据溯源条和 54/54。

## 1:10–2:05：发现异常

> 上方用相同零基线对比全部声量和负面筛查量，下方单独表示风险词占比，避免双轴造成虚假相关。峰值出现在 8 月 2 日，来源以微博公开内容为主，但同时覆盖 RSS、校园论坛和新闻媒体。

快速展开一次“查看图表数据表”，证明数值可核对。

## 2:05–3:05：聚合与优先级

> 54 条证据稳定形成食品与餐饮安全、数字服务保障、反诈与缴费安全三条事件线。矩阵横轴是负面筛查占比，纵轴是描述性热度，圆面积表示样本量。热度不是概率，密集标注虽会错位，数据点始终保持真实坐标。

指向风险矩阵和态势读数。

## 3:05–4:05：事件下钻核验

点击“【校园食品与餐饮安全】 阶段追踪”。

> 事件详情展示它在四个时间窗的 6、12、9、1 条证据，来自四类来源，并列出风险词命中。往下是 28 条原始证据入口。这样每个结论都能回到原文和时间。

关闭弹窗，指向来源—事件证据关系网。

> 关系网表示证据归属，不是社交转发链，我们特意把这个边界写在图表标题下。

## 4:05–4:30：处置闭环

> 高风险事件会进入待处置队列，可记录确认、调查、解决或误报，并生成只允许引用当前事件证据 ID 的简报。数据采集失败、登录失效或验证码不会被伪装成成功。

## 4:30–4:48：分析实验室

打开“分析实验室”，保持选中当前演示项目。

> 这里不是另一套大屏。词频、情感趋势、事件排行、来源结构和高级模型都绑定同一个监测项目。当前 54 条样本只有 4 个观测日，因此 ARIMA 和 SIR 会明确提示数据不足，不会为了画出结果而补模拟数据。

## 4:48–5:00：证据收尾

> 现有 42 项自动化测试全部通过，固定演示数据重复加载不会产生重复记录。我们当前能证明的是可追溯、可复现的研判工作链；真实平台覆盖和模型准确率仍需授权数据和独立标注集验证。

## 现场容错

- 公网不可用：继续使用固定离线案例，不运行 RSS/微博采集。
- 图表没有出现：选择“高校校园安全与民生服务｜国赛演示”并点“刷新全部图表”。
- 页面被缩放：按 `Ctrl+0`，再刷新。
- 时间不足：只演示首屏、声量演化、风险矩阵、餐饮事件下钻和分析实验室的数据不足提示。
