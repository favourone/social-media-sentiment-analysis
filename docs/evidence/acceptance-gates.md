# 验收门槛

## 可证伪改进假设

对于使用大屏筛选和预测的演示者，把请求校验、关联评论统计、数据来源标识和离线模型评估加入正常路径，应使关键 API 合约通过率从 2/10 提升到 10/10，同时不破坏合法查询与代码可编译性；机制是消除静默回退、错误聚合和请求时副作用。

## 必须满足

1. 固定的 10 个关键 API 合约场景全部通过。
2. 评论计数同时服从日期范围和其所属帖子的主题范围。
3. 日期、预测步数等非法参数返回结构化 400，不产生 500。
4. 未知话题或过滤后数据不足时返回明确的 404/422，不使用内置序列伪造结果。
5. 数据 API 提供来源类型、证据状态和限制；缺少清单时标记为推断或未知。
6. `/api/model_metrics` 只读取离线评估产物，缺失时安全失败，不训练模型、不覆盖检查点。
7. 模型词表只由训练集构建，训练/验证/测试采用固定种子和分层拆分，验证损失来自真实计算。
8. 默认关闭 Flask debug，MongoDB 为显式启用的可选依赖。
9. 自动化测试和 `compileall` 通过，Git 差异不包含数据集、模型或无关用户文件。

## 停止或回滚条件

- 合法主路径端点出现新增 5xx。
- 为通过测试而重新引入未标注模拟数据或硬编码展示指标。
- 评估改动无法区分训练、验证和测试数据。
- 需要覆盖用户已有数据或模型文件才能完成验证。
