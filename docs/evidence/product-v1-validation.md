# 产品 V1 验证记录（2026-07-22）

## 问题与假设

目标用户是需要完成舆情演示和初步研判的分析人员。原项目已有分析大屏，但缺少登录、正式业务存储、采集任务、去重、失败恢复和报告，因此无法独立完成“获得数据到交付结果”的正常任务。

可证伪假设：加入单管理员保护、SQLite 业务存储、可观察任务、合规采集适配器和报告后，固定自动化夹具应完整通过导入、去重、分析、预警和导出流程，同时保持原有 7 项回归通过；新增核心模块覆盖率不低于 80%，且采集或模型失败不能触发未标注模拟结果。

## 方案选择

| 选择 | 优点 | 主要代价 | 决定 |
|---|---|---|---|
| 继续使用 JSON 文件 | 改动少 | 无任务事务、账号和可靠去重 | 拒绝作为正式业务存储，仅保留导入兼容 |
| SQLite + 单 RQ Worker | 符合单管理员单机范围，部署和备份简单 | 不适合高并发和多机写入 | 采用 |
| PostgreSQL + 多 Worker | 扩展性强 | 超出首版用户规模和运维目标 | 延后 |
| 复制第三方爬虫源码 | 集成直接 | 许可证、更新和安全责任不清晰 | 拒绝 |
| 外部 MediaCrawler 适配器 | 高关注、支持浏览器授权和多种导出 | 非商业许可证、平台变更、需要人工登录 | 教学/竞赛场景采用，固定版本并隔离安装 |
| 官方微博接口 | 长期合规性更清晰 | 需要授权、额度和实际凭据 | 商业化或公开部署时替换 |

MediaCrawler 选择依据来自其 GitHub 主仓库与许可证；本项目只记录适配代码和固定提交，不提交第三方源码、Cookie 或登录状态。

## 失败试验与修正

1. `cv` 在受限执行环境里创建 `tempfile` 子目录被 Windows ACL 拒绝；改为在授权执行下使用项目内忽略目录复测，29 项通过。该问题属于执行沙箱，不是项目运行断言失败。
2. 低多样性文本使 LDA 产生空词典并抛出异常；改为组件级失败隔离，完整任务仍返回摘要，并明确标记 LDA 不可用。
3. 最初覆盖率把全部旧代码纳入门槛，结果为 68%；验收目标定义的是“新增核心模块”，因此 CI 明确锁定新增采集、任务、SQLite、报告和 V1 API 范围，实测 82%，未通过排除未覆盖的新代码来降低门槛。
4. 当前主机没有 `docker` 命令，无法执行 Compose 解析、镜像构建、持久卷重启和冷启动检查；Docker 文件存在不等于部署已验证。
5. 性能脚本首次直接运行时缺少项目根目录引导，产生 `ModuleNotFoundError: config`；加入与现有脚本一致的根目录路径后重跑成功，首次失败没有被计入性能样本。

## 未验证与下一实验

- 未使用真实微博账号运行固定提交的 MediaCrawler；当前只通过伪外部仓库、伪进程和真实导出解析器验证接口与失败恢复。
- 未连接实际 Redis 服务运行 RQ Worker；已验证 inline 模式、RQ 不可用错误和 Docker 配置文件，真实队列仍需在装有 Docker/Redis 的机器测试。
- 未进行代表性用户任务、跨浏览器视觉检查、键盘/读屏人工检查、并发压测或公开互联网部署。
- 没有真实社交媒体独立标注集，因此没有新增情感准确率、F1、预警精度或业务影响主张。
- 下一最高价值实验是在获得授权的前提下，以一个已知活跃关键词完成一次人工扫码冒烟测试，保存任务状态、原始来源、去重统计和报告，然后由一名目标用户按固定任务脚本试用。
