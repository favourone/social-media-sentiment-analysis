# 评审叙事与演示路径

作品正式名称为“高校校园公共安全与民生服务舆情态势可视化平台”，界面简称“校园舆情雷达 V2”。目标用户是高校管理人员及校园公共安全、后勤和信息服务分析人员。

## 30 秒版本

这不是一个只展示图表或罗列模型的通用舆情页面，而是面向高校校园食品与环境安全、治安反诈、设施与数字服务的一条可审计研判工作链：发现异常、聚合事件、核验证据、记录处置。国赛态势总览把时间、来源、优先级、事件演化和证据归属组织成可下钻叙事；固定 54 条合成记录保证无网络可复现，页面不会将它伪装成真实校园事件。当前自动化测试、新竞赛后端覆盖率和真实采集边界以最新验证记录为准。

## 3 分钟演示路径

1. 从登录页进入工作台，说明单管理员、CSRF 和敏感配置边界。
2. 在“今日态势”载入离线演示案例，强调数据性质、54/54 样本和时间方法。
3. 用声量演化与来源构成完成“发现”，用 3 事件风险矩阵完成“聚合”。
4. 点击餐饮事件，展示 4 个时间窗、4 类来源和 28 条原始证据。
5. 指向来源—事件证据关系网，说明它不代表转发或因果传播。
6. 在“预警处置”把一个预警从新建流转到调查中，并展示审计记录。
7. 生成事件简报，强调每个引用都对应当前数据库中的真实信号；再展示 PDF/CSV 报告兼容能力。
8. 打开“分析实验室”，说明词频、趋势、排行、来源和高级模型都绑定当前监测项目；用 ARIMA/SIR 的数据不足提示证明系统不会静默填充模拟数据。
9. 打开系统设置，说明 Scheduler、Webhook 审计、授权采集边界和确定性简报模式。
10. 展示 42 项测试和新竞赛模块 93% 覆盖率，以可复现证据收尾。

演示使用显式导入的非敏感样本，不依赖现场网络或扫码。真实采集只作为授权后的扩展冒烟测试，不伪装为已验证能力。

## 常见问题的证据化回答

- **项目解决了什么真实问题？** 高校食品安全、反诈提醒和公共服务故障的信息分散在校务公开、校园社区、媒体与社交平台中，管理人员难以快速看清事件演化并回到证据核验；平台把这些步骤组织成可追溯闭环。
- **为什么聚焦高校校园？** 校园公共安全与民生服务拥有明确的用户、事件边界和处置责任链，比“全网万能舆情”更适合用数据可视化表达发现、响应与改进过程。
- **为什么选择 SQLite？** 当前是单管理员单机产品，SQLite + 单 Worker 能提供事务、唯一约束和可备份性；PostgreSQL 会增加尚无用户规模证据支持的运维成本。
- **如何处理反爬？** 使用用户授权浏览器会话、低并发、暂停和重试，不绕过验证码或访问控制；适配器与第三方源码隔离。
- **为什么选择 MediaCrawler？** 它是高关注且仍维护的公开仓库，支持微博和结构化导出；但许可证限制非商业用途，所以只作为外部教学/研究适配器，商业化必须换授权接口。
- **模型准确吗？** 没有真实独立标注集，不能给出新的准确率/F1 主张。预警中的词典标签只是透明筛查基线。
- **如何证明没有伪造数据？** 未配置或未确认许可时测试任务进入 `paused`，错误码为 `license_confirmation_required`，入库为 0；ARIMA/SIR 数据不足时返回明确不可用。
- **Docker 是否验证过？** 当前主机没有 Docker 命令，因此配置已实现但冷启动和持久卷重启仍是 unknown。
- **下一步最高价值实验是什么？** 合规完成一次微博扫码任务并保存来源/去重/失败证据，再让目标分析人员按固定脚本完成一次导入到报告任务。
